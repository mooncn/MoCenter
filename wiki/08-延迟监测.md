# 08 延迟监测

侧边栏 → **延迟监测**：查看各主机到指定目标的 RTT 曲线、丢包率与波动，用来判断“卡”是网络问题还是主机问题。

## 1. 探测目标从哪来

探测目标配置在**被控机 Agent** 上（`-latency-targets`，逗号分隔），例如：

```bash
-latency-targets "icmp:1.1.1.1,tcp:1.1.1.1:443,http:https://example.com"
```

支持三种方式：

| 写法 | 说明 |
|---|---|
| `icmp:1.1.1.1` | ICMP 回显（需要目标不拦 ICMP，部分云厂商会丢） |
| `tcp:1.1.1.1:443` | TCP 握手耗时（最通用，推荐） |
| `http:https://example.com` | HTTP 请求总耗时（含 DNS+TLS，适合测站点可用性） |

改完目标后重启 Agent 生效；未配置时该主机没有延迟数据。

## 2. 页面用法

1. 选择主机；
2. 选择探测目标（列出该机上报的全部目标）；
3. 查看：
   - **曲线**：所选时间窗内的 RTT 走势（悬停看具体值）；
   - **统计**：最新值、最小/最大、平均、样本数、丢包率。

时间窗与仪表盘一致（1 小时 / 8 小时 / 24 小时）。

📷 **截图占位**：`延迟监测-曲线`

## 3. 判读建议

| 现象 | 可能原因 |
|---|---|
| 延迟整体抬高但曲线平滑 | 链路拥塞、跨地域绕路、运营商问题 |
| 周期性尖刺 | 目标侧限速、定时任务占用带宽 |
| 丢包率上升但 RTT 正常 | 链路拥塞或中间设备丢包 |
| 全部目标都超时，但终端能连 | 被控机出站被限（安全组/代理），或 ICMP 被禁（改用 tcp/http） |
| 只有 http 目标慢 | 目标站点本身慢或 DNS 解析慢 |

## 4. 数据保留

- 原始采样保留 **7 天**；更早的数据会先归档（gzip）再清理，避免数据库无限膨胀。
- 归档文件在服务端数据目录下，需要长期留存请自行转存。
