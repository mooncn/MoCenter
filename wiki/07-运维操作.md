# 07 运维操作

侧边栏 → **运维操作**：批量命令、远程升级 Agent、文件分发。
这三个功能都走已认证的长连接，不需要开放被控机入站端口。

## 1. 批量命令

1. 目标主机：勾选一台或多台在线主机；
2. 命令内容：按目标系统填写（Linux 用 shell 语法，Windows 用 cmd/PowerShell 语法）；
3. 点执行，下方表格逐台显示：执行中 / 成功 / 失败 / 已拦截，并给出输出摘要。

- 单条命令的输出有大小上限，超出会被截断并标注；要留完整输出请让命令自行重定向到文件，
  再用「文件管理」下载。
- 命令以 Agent 服务账号身份执行；所有命令与结果写操作审计。
- 结果通过命令 ID 定向回投，页面刷新/切换主机不会串台。

## 2. 远程升级 Agent

两种升级包来源：

| 来源 | 适用 | 要求 |
|---|---|---|
| **本地 pkg（免签名）** | 已把升级包放进服务端 `data/packages`（或 `-pkg-dir`） | 视为可信，直接经长连接下发；`data/packages` 里的包默认只有本机管理员能写 |
| **在线链接（需签名）** | 从 HTTPS 地址分发 | Agent 必须配置 `-upgrade-pubkey`（Ed25519 公钥），签名不匹配一律拒绝 |

操作步骤：

1. 选择「升级包来源」；
2. 选择目标主机（可多选）；
3. 填**目标版本**（本地 pkg 模式默认取服务端版本，可按包修改）；
4. 可选“强制升级”（版本相同也执行）；
5. 提交后观察每台主机的进度与结果。

> 升级过程中 Agent 会短暂离线并自动重启；升级失败会保留旧二进制（`.bak`），
> 看该机日志确认原因。离线主机不会被升级。

📷 **截图占位**：`运维操作-远程升级`

## 3. 文件分发到主机

适合把安装包、脚本、驱动分发到一批主机：

1. 选择文件（支持大文件，分片传输并校验）；
2. 填 **Agent 端目标路径**（必须是绝对路径，如 `/etc/mocenter/files/app.tar.gz`、
   `C:\mocenter\files\app.zip`）：
   - 该路径若不在 Agent 的 `-file-roots` 内，会被拒绝（本功能沿用文件根目录沙箱，
     与「文件管理」的整机访问不同）；
3. 选择目标主机 →「分发文件」，页面显示每台的进度与结果。

- 分片发送、逐片确认；中断可重试。
- 与「文件管理 → 上传」的区别：文件分发面向**批量**与**沙箱内固定目录**；
  文件管理面向**单机整机运维**（可浏览、修改任意路径）。

📷 **截图占位**：`运维操作-文件分发`

## 4. 审计

三个功能都会写审计（操作人、目标主机、命令/文件名、结果、是否被拦截）。
到「操作审计」页可按类别、时间、关键字过滤并导出 CSV，详见 [12](12-备份恢复与审计.md)。
